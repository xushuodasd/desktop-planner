# 需求与验收 —— 桌面悬浮工作计划板（项目代号 desktop-planner）

> 状态：**待批准（v0.1 草案）**；版本：v0.1；负责人：研发总监；更新：2026-11-17
> 来源：老板直接消息（2026-11-17，原话见 §1）；调研报告：[现成方案调研-2026-11-17.md](<../research/现成方案调研-2026-11-17.md>)

## 1. 来源与产品边界

- 用户角色：老板本人使用（单机单用户；事实：直接消息，无其他用户资料）。
- 原始需求来源：老板 2026-11-17 消息——"win11 适配；桌面悬浮、好看的图标、点开展开半透明；逐行记录每日工作计划（如 9-10点开会）；记录已办（如 9-10：面试）；JSON 格式存储方便 AI；先找现成的，没有就自己做一个。"
- 未知项：无阻断未知。数据存放位置、软件名称按总监默认执行，老板可在验收时提出调整。
- 本期范围（一期 MVP）：单机、免安装、纯本地的 Win11 桌面悬浮待办工具。
- 排除范围（二期候选，一期不做）：历史多天/周视图、报表导出、AI 自动整理与提醒、数据加密、云同步、安装包与自动更新、主题自定义系统。
- 排除原因：一期目标是老板尽快拿到能日常使用、AI 可读数据的可用版本；扩展项价值待一期用后反馈再定。

## 2. 需求条目（一期，全部为"必须"，除注明外）

### REQ-001：桌面悬浮球
- 类型：功能；来源：老板消息。
- 用户故事：老板需要桌面常驻一个好看的悬浮图标，以便随时一键打开工作计划。
- 主流程：启动程序后桌面出现圆形悬浮球（约 48–64px，设计精致、有质感）；鼠标按住可拖动到任意位置；松开后位置被记忆，程序重启后恢复。
- 异常/边界：拖动超出屏幕边缘时吸附在屏幕范围内；不遮挡任务栏常态交互。
- 验收标准：给定程序已启动，观察桌面出现悬浮球；执行拖动，悬浮球跟随鼠标；重启程序，位置与关闭前一致。
- 验证方式：人工演示（验收时老板亲自看）。

### REQ-002：点击展开半透明面板
- 类型：功能；来源：老板消息。
- 用户故事：老板需要点击悬浮球展开一个半透明面板，以便不遮挡桌面内容的同时查看与编辑计划。
- 主流程：单击悬浮球展开面板（约 360×560，圆角、半透明毛玻璃质感、Win11 风格、置顶）；再次点击悬浮球或按 Esc 收起。
- 异常/边界：面板不抢走当前工作窗口焦点输入；半透明度在设置中可调（约 60%–100%）。
- 验收标准：给定面板已展开，观察其悬浮于其他窗口之上且背景透出；收起后面板消失、悬浮球仍在。
- 验证方式：人工演示。

### REQ-003：今日计划（逐行）
- 类型：功能；来源：老板消息。
- 用户故事：老板需要逐行记录当日工作计划（时间段+事项），以便一天的工作一目了然。
- 主流程：面板上半区为"今日计划"，显示当天日期；输入"时间段（如 9:00-10:00）+ 事项（如 开会）"回车即新增一行；每行可编辑、可删除；按时间排序显示。
- 异常/边界：时间段允许留空（纯文字条目）；条目过多时面板内滚动。
- 验收标准：给定空列表，执行添加"9:00-10:00 开会"，观察到新增一行并持久；重启程序后该行仍在。
- 验证方式：人工演示 + 程序内数据自检。

### REQ-004：完成流转（计划 → 已办）
- 类型：功能；来源：老板消息（"记录已办"）。
- 用户故事：老板需要把做完的事从计划划到已办，以便区分"要做的"与"做过的"。
- 主流程：计划行前有勾选框，勾选后该行自动移入下半区"已办"，并记录完成时刻。
- 异常/边界：误勾选可在已办行上"撤销"回到计划区。
- 验收标准：给定计划行"9:00-10:00 开会"，执行勾选，观察到该行出现在已办区且带时间；重启后状态保持。
- 验证方式：人工演示。

### REQ-005：已办手动记录
- 类型：功能；来源：老板消息（示例"9-10：面试"为非计划内完成事项）。
- 用户故事：老板需要直接补记已发生的事（不在原计划中的），以便已办完整。
- 主流程：已办区提供输入行（时间段+事项），回车新增；可删除。
- 验收标准：给定已办区，执行添加"14:00-15:00 面试"，观察到新增一行并持久。
- 验证方式：人工演示。

### REQ-006：JSON 本地存储（AI 可读）
- 类型：功能（核心差异化）；来源：老板消息。
- 用户故事：老板（及其 AI 程序）需要直接读写本地 JSON 文件，以便 AI 侧自动整理、分析每日工作。
- 主流程：数据保存于软件目录 `data/workboard.json`（UTF-8）；结构见 §5 数据模型；每次修改即时保存（原子写：临时文件+替换，防止写坏）。
- 异常/边界：文件被外部程序修改后，程序下次读写以文件最新内容为准（读入校验，不合法字段忽略并保留原文件备份）；JSON 损坏时程序不崩溃，提示并以 .bak 备份重建。
- 验收标准：给定程序内已录入数据，用记事本打开 `data/workboard.json` 能看到与界面一致的清晰 JSON；手工改动某条目文本后重启程序，界面显示改动后的内容。
- 验证方式：人工演示 + 独立审查核对数据模型文档。

### REQ-007：托盘常驻与开机自启
- 类型：功能；来源：总监补充（常驻类软件的标配，老板未反对）。
- 用户故事：老板需要程序在后台常驻、可开机自启，以便第二天不用手动打开。
- 主流程：系统托盘有图标，菜单：显示/隐藏悬浮球、开机自启（开关，默认关）、退出；点击面板"收起"不退出程序。
- 异常/边界：开机自启开关即时生效，无需管理员权限。
- 验收标准：执行退出，悬浮球与托盘图标消失、进程结束；开启自启后托盘菜单显示已开启。
- 验证方式：人工演示。

### REQ-008：免安装、离线、无广告
- 类型：约束；来源：老板消息 + 调研结论 R-d。
- 主流程：交付形态为绿色文件夹，双击"启动悬浮工作台"即用；运行全程不联网、无账号、无广告弹窗。
- 验收标准：断网状态下完整走一遍 REQ-001~005 主流程无异常；运行期间无网络进程连接（独立审查抽查）。
- 验证方式：人工演示 + 审查。

### 非功能指标
- 兼容：Windows 11 为主，Windows 10 尽量兼容；中文界面。
- 性能：启动到悬浮球出现 ≤ 5 秒（本机）；常驻内存 ≤ 200MB（技术栈决定，见设计文档）。
- 数据安全：数据文件仅存本机；程序卸载/删除文件夹即数据随文件夹保留在 `data/` 内，不隐藏、不扩散。

## 5. 数据模型（workboard.json，随 REQ-006 交付并在 README 说明）

```json
{
  "schemaVersion": 1,
  "app": "desktop-planner",
  "days": {
    "2026-11-17": {
      "plans": [
        { "id": "p-1731810000000", "time": "9:00-10:00", "text": "开会",
          "createdAt": "2026-11-17T09:00:00+08:00" }
      ],
      "dones": [
        { "id": "d-1731813600000", "time": "9:00-10:00", "text": "面试",
          "source": "manual", "completedAt": "2026-11-17T10:00:00+08:00" }
      ]
    }
  },
  "settings": { "opacity": 0.85, "theme": "auto", "autostart": false,
                "ballPosition": { "x": 100, "y": 200 } }
}
```
- 字段含义：`plans`=当日计划行；`dones`=当日已办行（`source: manual|from-plan` 区分手动补记与计划勾选流转）；`settings` 为界面与行为设置。AI 读写以 `days.<日期>` 为单位即可。
