# 设计系统与视觉规范 —— 悬浮工作台（Obsidian Glass）

> 本文件是**强制规范**，不是参考建议。任何 UI 改动（含 AI 生成的改动）都必须先读完本文，
> 并在提交前对照第 8 节自检。与本文冲突的实现一律视为不合格。

## 1. 设计信条

1. **像一件静物，不像一个软件**：没有多余的按钮、边框和颜色；界面上每多一个元素，都必须能说清它存在的理由。
2. **一个强调色**：全界面只有蓝色（`--accent`）用于「当前值 / 主操作 / 选中态」。不允许出现第二个彩色语义。
3. **就地发生**：编辑、选时间、删除确认都在原位完成，不用系统对话框、不用模态弹窗、不跳页。
4. **可逆优先**：能撤销就不拦；必须拦的危险操作，用行内二次确认，并自动超时还原。
5. **材质分层，不靠描边**：用「渐变底 + 顶部内高光 + 1px 内描边 + 外投影」表达层级，禁止用粗边框分割区域。
6. **动效是标点，不是装饰**：只解释状态变化（展开/收起/进入/离开），不炫技；所有动画必须可打断、不阻塞输入。

## 2. 视觉令牌（`app/style.css` 顶部）

| 类别 | 规则 |
|---|---|
| 字体 | `--font`：SF Pro Display → Segoe UI Variable → Segoe UI → 微软雅黑；数字一律 `font-variant-numeric: tabular-nums` |
| 圆角阶梯 | 面板 24 / 卡片 18 / 控件 13 / 芯片与滚轮带 10；**内圆角 = 外圆角 − 内边距**，保持同心 |
| 间距 | 面板左右 16，底部 26；行内上下 11；控件高 38（编辑态 30/28 的小号控件按层级递减） |
| 文本层级 | 日期标题 21/650/-0.4px；同行星期 13.5/550；正文 13.5/450/1.4；元信息 10.5/400；时间 12–13.5/600 |
| 颜色 | `--text-1` 主文 / `--text-2` 次文 / `--text-3` 弱文；分隔线 `--line`（≤8% 白）；危险色 `#ff453a` 仅用于删除确认 |
| 材质 | 卡片 = `--card-1→--card-2` 渐变 + `--card-glow` 内高光 + `--card-ring` 1px 内描边 + 外投影 |
| 透明度 | 面板 opacity 由设置驱动（`--panel-alpha`），任何新元素不得再叠加不透明实底 |

## 3. 组件规范

### 3.1 面板与顶栏
- 面板圆角 24，`backdrop-filter: blur(52px) saturate(1.75)`，`inset 0 1px 0 rgba(255,255,255,.07)` 内高光。
- 顶栏：日期和星期同行，星期用较小的次文字；下面接全宽分段控件。

### 3.2 分段控件（待办 / 已办）
- 高 32、胶囊轨道、选中块**必须比轨道亮**（深色下 thumb ≥ 14% 白，轨道 ≤ 5% 白）。
- 选中块带内高光与投影，滑动 360ms `--spring`；计数使用 `text-3`，选中时用 `--accent`。

### 3.3 列表行
- 无卡片底，只用细线分隔；分隔线左右各缩进 8px（`::after` 实现），最后一行无线。
- 悬停或键盘聚焦时出现操作按钮（透明度 0 → 1，位移 2px → 0）；按钮 26×26 圆形，图标 12px。已办行的按钮与右对齐的完成时间共用一栏，切换时正文宽度保持稳定。
- 时间和完成时间使用次文字色。滚动条默认低对比，悬停时增强对比度。
- 跨天待办与当天待办使用相同的行布局，添加日期只保存在数据中。
- 勾选框 18px 圆形，勾选后渐变填充 + 打勾缩放动画；勾选后整行淡出右移 200ms 再归入已办。

### 3.4 输入卡
- 外圆角 18、内边距 4、控件 38；时间文字是**纯文字**（无底色），右侧一条 16px 高的 1px 分隔线。
- 空输入框自动聚焦时使用中性描边。输入内容、键盘聚焦选时按钮或展开时间滚轮时使用蓝色描边。
- 展开选时间时卡片高度过渡 300ms，滚轮延迟 40ms 淡入上浮；不出现「完成」类确认按钮。

### 3.5 时间滚轮
- 高度 102（3 行 × 34），`scroll-snap: mandatory`，分钟 5 分钟一档。
- 选中行是发光胶囊（`--picker-band` + 1px 描边），数字按距离分层：20/650/100% → 14/50% → 12/20%。
- 滚轮上下用 `mask-image` 渐隐，禁止硬裁切；滚动实时更新外部时间文字。
- 左键按住数字区可上下拖动，拖动时跟随鼠标，松手吸附到最近一档。单击相邻数字可选中该档，鼠标滚轮照常可用。
- 一个滚轮组件（`createWheelPair`）同时服务底部输入卡与行内编辑，禁止各写一套。

### 3.6 行内编辑
- 点编辑后原行替换为编辑卡（圆角 14，玻璃材质），**不弹窗**。
- 时间芯片 30px 高，点击在卡内展开与底部同一套滚轮。
- 正文用 `textarea` 自动增高（34 → 116px 封顶后内部滚动），禁止单行 input 截断。
- 操作区右下角：`取消`（`text-2`）+ `保存`（`--accent`）纯文字按钮，高 28。
- 键盘：`Enter` 保存、`Shift+Enter` 换行、`Esc` 取消。

### 3.7 删除确认
- 禁止 `window.confirm`、禁止模态弹窗、禁止直接删除。
- 点删除后该行**就地**变为「删除这条记录？ 取消 / 删除」，底色 7% 危险色，行高基本不变。
- 3.5 秒无操作自动还原；点其他区域、按 `Esc` 也还原；只有点「删除」才真正删除。

### 3.8 空状态
- 居中于列表区域（绝对定位铺满 + flex 居中），28px 细圆环 + 一行弱文字。
- 任何自定义 `display` 的可隐藏元素必须补 `xxx[hidden] { display: none }`（UA 的 `[hidden]` 会被作者样式覆盖）。

### 3.9 Toast
- 底部居中胶囊，深色半透明 + 模糊 + 投影；只用于失败/提示，不用于成功确认。

### 3.10 回顾与托盘
- 回顾只显示已办。日视图在窗口标题区显示日期和完成数，周、月视图另保留每日小计。搜索命中和导出沿用蓝色。
- 回顾页用遮盖度较高的半透明底色。时间列一般为 64px，包含历史时间段时用 96px。
- Electron 托盘菜单依次放置面板与回顾、自启与设置、退出。首项文案对应面板状态。WinForms 托盘的首项为「打开面板」。

## 4. 动效规范

| 场景 | 时长 | 曲线 |
|---|---|---|
| 展开 / 收起（卡片、滚轮、编辑） | 300ms | `--spring` = `cubic-bezier(0.32,0.72,0,1)` |
| 行进入、编辑卡进入 | 260–340ms | `--spring` |
| 勾选 / 删除确认 / 悬停 | 160–220ms | ease 或 `--spring` |
| 分段控件滑块 | 360ms | `--spring` |
| 贴顶滑出 / 收起 | 460ms / 400ms | 窗口整体平滑加速、减速（主进程时间基准，16ms 帧） |

- 动画只改变 `opacity` / `transform` / `height` 类可合成属性；不得用 `display` 切换做过渡。
- 不得添加无限循环动画、发光呼吸、粒子、视差等装饰性效果。
- 所有出现动画必须同时定义「离开」路径，且可在 300ms 内被反向操作打断。

## 5. 交互规则

- 长文本就地展开/收起（仅在 `scrollWidth > clientWidth` 时启用），支持点击、Enter 和空格。
- 危险操作：行内二次确认；删除、清空等不可逆操作一律走 3.7。
- 可逆操作：完成、撤销直接执行，不做确认。
- 键盘：`Enter` 提交、`Esc` 逐层退出（确认 → 滚轮 → 编辑 → 收起面板）。
- 点击空白：收起滚轮、取消删除确认，不关闭面板。
- 任何点击都不应导致列表重排跳动；行高在状态切换时保持稳定。

## 6. 禁止清单（出现即不合格）

1. 使用浏览器/系统默认控件外观（`confirm`、`prompt`、原生 select、默认按钮灰底）。
2. 引入第二种彩色强调（绿勾按钮、橙色标签等），勾选态除外。
3. 用粗边框、分割线墙、卡片套卡片来表达层级。
4. 弹窗式编辑/删除/选时间。
5. 单行截断却无法查看全文。
6. 硬编码颜色（必须用 `:root` / `body[data-theme]` 令牌，亮暗两套都要给）。
7. 只适配深色、不检查浅色；只适配短文本、不检查长文本；只检查有数据、不检查空态。
8. 直接改样式却不同步 `README.md` / `design.md` / 本文件。
9. 使用默认 Electron 图标，或手工塞一张来源不明的 png/ico；应用与托盘图标统一由 `scripts/make-icons.py` 生成、`scripts/afterPack.js` 写入 exe。

## 7. 代码约束

- 渲染层纯 vanilla JS，禁止引入 UI 框架或图标库；图标以内联 SVG 路径（`ICONS`）维护。
- 所有 IPC 走 `preload.js` 白名单，渲染层不触盘。
- 新增交互状态放进 `state` 或明确的模块变量，禁止散落魔法值。
- 新的视觉数值（圆角、时长、颜色）先加令牌，再使用。

## 8. 提交前自检（逐项打勾）

- [ ] 深色 / 浅色两套主题都看了一遍，没有硬编码颜色残留
- [ ] 空列表、单条、多条、超长文本、跨行编辑五种状态都验证过
- [ ] 所有圆角符合阶梯，控件高度成组一致（38 / 30 / 28）
- [ ] 只有一处蓝色焦点；危险色只出现在删除确认
- [ ] 展开/收起动画可打断，无跳变、无遮挡、无滚动条意外出现
- [ ] 键盘路径：`Enter` / `Shift+Enter` / `Esc` 行为正确
- [ ] 控制台无报错；`node --check app/renderer.js` 通过
- [ ] 文档已同步（README 功能摘要、design.md ADR、本文件）

## 9. 修改流程

1. 先读本文与 `design.md` 的相关 ADR，确认改动不违背既有决策。
2. 只做被要求的改动；不顺手重排、不更换既有风格。
3. 设计有取舍时，在 `design.md` 追加一条 ADR（背景 / 决定 / 代价）。
4. 实现后用真实界面验证（本机无法起 GUI 时，用 `scripts/test` 或临时预览页验证后如实说明）。
5. 更新 `README.md`「当前状态」与功能摘要，再交付。
